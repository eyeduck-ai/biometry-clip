> 歷史診斷：使用者後續確認 v0.3.3 正常並提交原生 14 站報告（8 通過／6 略過）。以下保留當時載入機制的研究；各版實測範圍與後續結果已整理於[驗證證據](validation-evidence.md#installed-calculator-checks)。

更新日期：2026-11-15。這份紀錄只處理浮窗顯示與載入狀態，不需要病人資料、biometry 測量值、圖片、PDF 或 API key。

## 已知觀察

- 使用者回覆已安裝 v0.3.1，並在 Barrett Universal II 開啟 Biometry 懸浮面板。
- 主代理接管 Chrome 時，看見浮窗外框／標題，但內文全白；未開始擴充功能讀取、儲存或貼入。
- 使用者確認兩個分頁中一個全白、另一個正常，之後回報：「我發現你接管chrome就會變白」。
- 主代理當時停止互動控制；後續僅在正式 HTTPS 父頁檢查浮窗 iframe 屬性與 frame metadata，並按一次正常重試。瀏覽器工具仍明確拒絕直接開啟 `chrome-extension:` 頁面；未讀取受保護內頁 HTML，也未使用替代路徑繞過該限制。
- 使用者後續確認目前為 v0.3.2，手動操作可正常顯示；同一輪 Barrett Universal II 的白畫面已取得下列直接證據。

在本次歷史診斷中，接管與變白的時間相關性成立；已確認直接載入機制，但未確認誰加入該屬性或其目的。當時完整的 14 站已安裝擴充功能端到端驗收尚未完成；後續使用者原生報告及其限制見[已安裝版本證據摘要](validation-evidence.md#installed-calculator-checks)。

## 已確認的直接白畫面機制

主代理在使用者目前的 Barrett Universal II HTTPS 分頁 `722863266`，只檢查父頁擁有的唯一 Biometry iframe 屬性及主頁 frame tree metadata，沒有讀取擴充功能文件內容。觀察如下：

| 項目 | 實際證據 |
| --- | --- |
| 使用版本 | 使用者確認為 v0.3.2，且未接管時手動顯示正常 |
| iframe `src` | 仍指向 Biometry 擴充功能的有效 `index.html` 網址，完整值存於 metadata |
| iframe `srcdoc` | **屬性存在，內容長度為 0**，即 `srcdoc=""`；不是單純未設定屬性 |
| 子框實際 committed URL | `about:srcdoc`，沒有載入 `src` 所指的擴充功能內頁 |
| 按正常「重新載入面板」後 | `srcdoc` 仍存在，iframe 仍全白 |
| 本專案原有外框程式 | 修正前未設定 `srcdoc`；目前證據尚未指出屬性由何者加入 |

**本次白畫面的直接機制已確認：空的 `srcdoc` 覆蓋有效的 `src`，使子框顯示空白 `about:srcdoc` 文件。** HTML 規範明定，兩個屬性同時存在時 `srcdoc` 優先；子框 URL 與此行為一致。[WHATWG HTML：iframe 的 srcdoc](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-srcdoc)

本機證據：[frame-metadata.json](../artifacts/root-cause-0.3.2/frame-metadata.json)、[白畫面截圖](../artifacts/root-cause-0.3.2/blank-frame.jpg)。已確認截圖檔存在；這些證據不包含擴充功能內頁 HTML、病人資料或測量值。

## 尚未確認

尚未確認是誰、何時及基於何種目的加入空 `srcdoc`，也未證明是特定擴充功能、瀏覽器控制程式或安全政策所為。接管的相關性不能單獨辨識寫入者。主頁沒有 console 錯誤不是內頁成功載入的證據；現在已有更直接的 `about:srcdoc` metadata。

v0.3.2 已實作載入就緒診斷與手動重試：面板啟動時回報 starting，完成首次渲染後回報 ready；未就緒滿 12 秒或明確啟動失敗時，外框顯示提示與「重新載入面板」。重試只重新載入內頁，保留視窗位置、大小及已儲存資料。狀態轉送僅含 phase、tabId、隨機 panelToken；不傳送病人資料或錯誤原文。舊內頁或其他分頁的狀態會被忽略。

上述 v0.3.2 診斷措施未清除新發現的 `srcdoc` 覆蓋，因此正常重試仍白。v0.3.3 已實作外框修正：只在使用者明確點重試或重新開啟時，移除 `srcdoc` 後恢復原本的 `src`。不新增持續監看／自動重試迴圈，不放寬權限或加入額外 `extension_ids`。下列 HTTP 開發頁回歸已通過，但**尚未驗證已安裝 v0.3.3 的接管情境，不能宣稱接管問題已完全解決**；14 站驗收狀態不因此改為通過。

## 使用者手動對照

可先檢查「未接管／放開後／重新開啟」；「接管時」保留已發生的現象與上述父頁 metadata，或日後使用者原本就需要接管時的自然觀察，無須為此反覆重新觸發。

使用不含病人資料的空白計算網站分頁即可。每一步只需記錄面板是否顯示頁籤、是否全白、可見狀態文字與時間；不要讀取、保存或貼入資料。

| 情境 | 使用者操作 | 紀錄內容 | 目前結果 |
| --- | --- | --- | --- |
| A：未接管 | 使用者自行開啟指定計算網站，點工具列的 Biometry 按鈕 | 網址類型、面板是否顯示 5 個頁籤、可見載入狀態 | 使用者已確認 v0.3.2 手動正常 |
| B：接管時 | 保留本次已發生的觀察，不為診斷反覆重新觸發 | 同一分頁是否變白；父頁 iframe 屬性／子框 URL | 已確認本次 `srcdoc=""` 覆蓋 `src`，子框 `about:srcdoc`；寫入者與目的未確認 |
| C：控制放開後 | 代理維持停止操作，使用者觀察同一分頁，不先重新載入網站 | 是否自行恢復、是否仍白、何時恢復 | 待手動記錄 |
| D：關閉後重開 | 使用者透過 Biometry 工具列按鈕收起，再開啟同一分頁的浮窗 | 是否恢復頁籤、載入狀態是否改變 | 待手動記錄 |
| E：v0.3.2 原有重試 | 已按一次正常「重新載入面板」 | 點擊前後 `srcdoc` 及顯示狀態 | 本次 `srcdoc` 仍存在，內文仍白，尚未恢復 |
| F：移除 `srcdoc` 修正後 | 在修正版本明確點重試／重開 | 是否移除覆蓋、恢復 `src` 載入及頁籤 | HTTP 開發頁兩路徑已通過；已安裝版本接管重測仍待驗，不宣稱完全修復 |

若兩個空白測試分頁結果不同，分別記為「分頁 A／分頁 B」即可。不要以正常分頁覆蓋白畫面的紀錄，也不要用一個分頁的恢復推定所有網站通過。不需要清除病人資料、重設瀏覽器設定或變更安全權限。

可回報的最小內容例如：`v0.3.2；Barrett；代理未接管；重開前全白，重開後看見頁籤；重試狀態文字：……`。若附截圖，只需空白測試頁面的浮窗範圍，先確認沒有姓名、ID、測量值或其他私人資訊。

## 使用者自行啟動的原生合成驗收

新增的「原生合成驗收」由使用者在未由助理接管 Chrome 時操作，入口為擴充功能 **設定 → 開啟原生合成驗收**。它使用真正的 Chrome 分頁／注入／訊息與儲存 API，並重用正式欄位橋接、session 與 library 服務，**不是模擬 Chrome API 的開發頁**。開啟頁面本身不啟動網站操作，主代理尚未啟動這個原生驗收，也沒有取得 14 站正式結果。

流程如下：

1. 使用者確認只送出合成資料，按「開始合成驗收」（Start）。先檢查隔離的多病人、多次測量、歷史快照與切換。
2. 按「驗證下一步」，只開啟本次新建的合成測試分頁，逐站檢查 OD／OS，以及雙眼網站的 OU。程式不使用原有病人分頁。
3. 遇到眼別、特殊模式或網站條款等前置條件，由使用者自行檢視與準備，再按「重試目前網站」；也可按「略過目前網站」保留未完成狀態。單眼網站無法可靠自動偵測眼別時，須先在原站確認訊息指定的 OD／OS，再勾選「已在原網站核對目前為 OD／OS」（介面依本次要求顯示當眼）後重試。報告記為 `manual-confirmed`，不當成 DOM 自動偵測。不自動接受法律條款、選臨床 IOL 或提交 Calculate。Solver Toric 的球面計算／IOL Power 前置流程也不代按。
4. 隨時按「匯出 JSON」，保存實際版本、各站各眼的欄位結果、儲存檢查與未完成原因，交回核對。`complete` 代表入口已處理完，不等於全部通過；基本欄位成功也不等於 Toric／LVC 成功。

測試資料使用獨立的 `biometryQa:` 儲存鍵：session 工作副本與本機 library 分開保存，不更動一般病人資料庫、一般工作副本或 API 設定。原生驗收的實際通過狀態須以使用者執行後的 JSON 判讀；目前仍為**未啟動／未實測**。直接 `chrome-extension:` 網址仍不在代理瀏覽器工具可存取範圍內，這個入口不代表取得該工具的額外存取權限。
