# Biometry-Clip 使用說明

介面預設英文；標題右上角可切換 EN／中文。本文以功能名稱說明，英文介面對應為 Data、Patients、Import、Launch、Settings。

## 安裝與更新

使用 Chrome 140 以上版本。在 `chrome://extensions` 啟用開發人員模式，載入包含 `manifest.json` 的發佈解壓資料夾，或從原始碼建置的 `dist`。更新時使用相同路徑，重新載入擴充功能，再重新整理原本開著的計算網站。

計算網站內點擊工具列圖示會開啟懸浮窗，可拖曳、縮放或收合。在其他頁面點擊則開啟較寬工作台，適合整理病人與辨識報告。工作草稿在不同視窗共享，變更會同步；若另一視窗先修改了同筆資料，系統會要求重新載入與核對，避免覆寫較新的內容。

## 一次輸入，跨站使用

1. 在來源網站開啟擴充功能，選「複製網站資料」；或在資料頁手動輸入、從匯入頁辨識報告。
2. 上方 **OD／OS 分頁**決定下方正在編輯哪一眼。兩眼各自保留數值，不會因切換而清空。
3. Toric、KC 與 LVC 是該眼的條件。LVC 可選無、近視雷射、遠視雷射或 RK；並非測量數值。舊資料中的未知狀態仍需核對。
4. 切到另一個支援網站，開啟擴充功能，選 OD、OS 或 OD+OS，執行貼入。
5. 核對原網站的眼別、模式、晶體及數值，再於原站執行計算。

常用欄位為 AL、ACD、LT、CCT、WTW、K1、K2、Target；依目前網站顯示其他必填／選填欄位及單位。「顯示所有欄位」只展開其他支援欄位，不會選取或改動資料。

單眼表單會依所選 OD／OS 切換網站的眼別控制，再填入該眼。OD+OS 只在目前表單確實偵測到受支援的雙眼輸入群組時使用。網站當下模式、未展開區塊或尚未完成的前置步驟，可能使部分欄位尚不可用；詳見[網站表](supported-sites.md)。

複製會收集有對應、可讀取的網站輸入值；貼入會使用目前草稿中有值且能明確對應的欄位。辨識不到的眼別、單位或晶體不會猜測。未提供的值不會以零補齊。複製／貼入不會自動送出公式計算。

## 病人與多次測量

工作草稿是跨分頁共用的暫存；要保留病人歷史，請將草稿儲存為測量。

- 新增病人並儲存測量，可加入日期、名稱與來源，單次測量包含 OD 與 OS。
- 選擇已存測量後載入草稿，再帶入不同公式。修改草稿不會直接改動歷史；儲存時選擇新增測量或更新原筆。
- 可編輯病人、刪除整位病人，或選取部分測量刪除。
- 可複製單筆測量為獨立資料，再編輯差異，適合保留不同測量版本。
- 定期匯出資料庫 JSON 作為備份；移除擴充功能或切換 Chrome profile 不會自動帶入舊資料。

病人與測量資料存於本機，不是雲端病歷系統。暫存草稿使用 `chrome.storage.session`；已儲存資料、偏好與金鑰使用 `chrome.storage.local`，沒有加密。

## 匯入的四種入口

| 入口 | 用途 |
| --- | --- |
| 複製網站資料 | 讀取目前受支援計算網站已填入的表單，不是螢幕 OCR |
| 貼上截圖 | 先用系統截圖，再於匯入頁貼上剪貼簿圖片；Windows 可用 Win+Shift+S、Ctrl+V |
| PDF／圖片 | 上傳或拖入 PDF、PNG、JPEG、WebP |
| JSON | 載入本專案結構化個案、病人資料庫或晶體目錄 |

沒有「貼上文字報告」入口。需要交換資料時，優先使用有版本與單位定義的 JSON。

### PDF 選頁與辨識

PDF 先建立頁面縮圖，可逐頁預覽／放大，以每組 12 頁瀏覽；每批最多選 **3 頁 PDF**，初始選第 1 頁。請選真正包含 biometry 測量的頁面；封面或只有晶體計算結果的頁面不一定有所需欄位。長報告可分批辨識。

程式先讀取原生 PDF 文字與座標。可解析時直接提取；影像型或文字不足時，才將所選頁轉成影像交給 OCR。預設 **PP-OCRv6 Small** 在擴充功能內執行；Tiny 可降低模型負擔，但結果仍須核對。選用雲端時，只有實際需要送出圖片才確認上傳。

處理中會顯示實際階段、經過分秒與不定進度條。模型無法提供可靠百分比，因此不會顯示推測的完成百分比；選頁、等待上傳確認不計入辨識時間。可以取消後重新選頁。

### 核對結果

寬畫面左側顯示來源，右側以 OD／OS 並排欄位顯示結果。窄懸浮窗先顯示雙眼資料，來源影像可展開。來源按鈕可跳到對應頁，並可切頁、縮放；修改數值或切換來源不會清除已編輯內容與勾選。

實際參與欄位辨識的 OCR 分數低於 **85%**，以暗紅框、底色及百分比提示。原生 PDF 與未回傳分數的模型顯示未知，不會自行生成分數。沒有紅色提示也應核對來源。

確認要帶入的欄位後儲存選取資料。若草稿已有值，預設不勾選覆蓋；使用者可主動選取。缺值、跨頁衝突或眼別不明會保留空白／提示，不推導缺少的 K 軸向。來源影像、信心分數與原始報告僅供這次核對，不存入病人資料庫或個案 JSON。

## 目前測試過的報告種類

主要報告為 **ZEISS IOLMaster 700**，已有兩種實際樣本：

| 類型 | 已驗證範圍 |
| --- | --- |
| 原生文字 PDF（8 頁） | 8 頁原生文字路由不呼叫 OCR；原第 6 頁完成數值比對與來源預覽核對 |
| 掃描／影像 PDF（7 頁） | 原第 2 頁以本機 PP-OCRv6 Small 辨識，完成數值比對與來源預覽核對 |

代表頁面共同的 **18 項數值**為每眼 AL、ACD、LT、CCT、WTW、K1、K1 軸向、K2、K2 軸向。原生 PDF、代表頁面本機 OCR 與實際安裝擴充功能的核對測試，與既有人工答案均為 18/18。掃描頁另外具有雙眼 Target；未測得的 TK 破折號仍為空值。

這是兩份樣本之代表頁面的結果，沒有驗證所有儀器、報告版本、掃描品質或所有頁面的欄位正確率。其他辨識專案中的 37 欄評分不等於本擴充功能已支援／驗證同一組欄位。**Argos 目前是網站儀器偏好與模式對應，尚未獨立驗證 Argos OCR 報告。**

另以去識別化代表頁比較過 Gemini 與官方 PaddleOCR API；這是有限樣本比較，不表示所有模型與帳戶都可用。可查閱 [v0.3.12](validation-0.3.12.md) 與 [v0.3.13](validation-0.3.13.md)。單元測試、報告辨識測試與 15 站跨站完整驗收是不同範圍，不應互相代替。

## 偏好參數與晶體

偏好參數在資料缺少時才套用至適用欄位，可於設定修改：醫師預設 `OPH`、Biometer `IOLMaster 700`、Toric SIA `0.05 D`、切口軸向 OD `180°`／OS `0°`。柱鏡顯示優先 `−ve`；EVO 的 CCT 固定使用 µm。必填病人識別欄可依設定將 ID／名稱帶入 initials／name，降低重複輸入。

晶體選擇與網站常數分開。跨站對照會區分精確型號、系列、群組及幾何；只有可明確辨識的對照才套用，模糊項目保留使用者處理。A constant、Lens Factor 等有各站差異，通常由原站選晶體後帶出，**預設不貼入常數**；需要時可啟用。

ESCRS 與其他站晶體／常數研究保留於[晶體文件](lens-transfer.md)及[ESCRS 研究](research-escrs-constants-039.md)，不可將某站的常數視為所有公式共用常數。

## JSON 交換與 API

個案、整份資料庫可匯出 JSON；資料庫匯入會新增獨立紀錄，不直接覆寫既有紀錄。現行格式仍為 `format: "biometry-clipboard"`、`schemaVersion: "1.3"`，相容匯入 1.0–1.2。晶體目錄另用 `biometry-lens-catalog` 格式。API 金鑰、來源影像、網站會話與計算結果不屬於病人交換資料。[完整結構](interchange.md)。

辨識模型設定區可展開官方 API 申請說明。一般模式只需貼上 Gemini API key 或 PaddleOCR AI Studio Access Token，再選模型；不需填網址。[API 設定與資料傳送說明](api-setup.md)。
